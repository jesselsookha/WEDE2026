# PART 1 — UNDERSTANDING THE ASSESSMENT

## 1.1 Purpose of the Part 3 PoE

The Part 3 Portfolio of Evidence (PoE) represents the **final stage** of your website development project.

This submission is **not** simply about creating additional pages or adding JavaScript functionality.

You are expected to demonstrate that you can:

- Improve an existing website based on feedback
- Implement professional web development practices
- Develop meaningful JavaScript functionality
- Apply Search Engine Optimisation (SEO) techniques
- Create appropriate documentation
- Maintain a GitHub repository professionally
- Deploy a working website online
- Present clear evidence of development
- Demonstrate academic integrity

**Important:** Unlike previous submissions, your work may be marked by a lecturer who has **never seen your project before**.

For this reason, your repository, README documentation, screenshots, references, changelog, deployment links and supporting evidence are **just as important as the website itself**.

---

## 1.2 What Part 3 Is — and Is Not

Part 3 is **not** a completely new website.

You are expected to **continue developing the website submitted in Part 2**, improve it based on lecturer feedback, and implement additional functionality using JavaScript, SEO techniques, deployment practices, and professional project documentation.

Before you begin any new development work, **revisit all feedback received for Part 1 and Part 2**.

This includes:

- ☐ Correcting HTML issues identified previously
- ☐ Correcting CSS issues identified previously
- ☐ Improving responsive design where weaknesses were identified
- ☐ Improving content quality where weaknesses were identified
- ☐ Fixing repository structure issues
- ☐ Improving README documentation
- ☐ Improving accessibility and usability concerns
- ☐ Recording all improvements in the README changelog

> **Marks are awarded for demonstrating improvement and evidence of development.**

---

## 1.3 How Marks Are Awarded (Read This Before Anything Else)

Many students focus only on creating a website. However, marks are awarded for **evidence of development, implementation quality and documentation**.

To achieve higher marks:

- ☐ Demonstrate meaningful functionality
- ☐ Provide evidence of implementation
- ☐ Explain development decisions
- ☐ Document improvements
- ☐ Reference external resources correctly
- ☐ Maintain professional repository practices
- ☐ Provide screenshots and supporting evidence
- ☐ Demonstrate a logical development process

**Remember:**

- A **good website with poor documentation** may lose marks.
- A **good website with strong documentation and evidence** is much easier to assess and will score higher.

### Important Note on Rubric Rows

One of the greatest misconceptions students have is believing that the rubric rows are **isolated requirements**.

They are not.

The rubric establishes the **minimum areas of assessment**, while the assignment brief provides the **broader expectations** of what a professional website should include.

For this reason, you should aim not only to satisfy the rubric but also to demonstrate **initiative, completeness, professionalism, and attention to detail**.
